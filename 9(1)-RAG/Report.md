# [9회차] RAG 과제 심화 보고서 (Report)

## 1. 임베딩 벡터 검색 거리 측정 방법(Similarity Metrics) 비교 분석

Pinecone 및 Elasticsearch의 벡터 검색 시 사용되는 거리 측정 방식(Similarity Metrics)에 따른 특성과 RAG 검색 성능 차이를 분석하였습니다.

### 1) 코사인 유사도 (Cosine Similarity) - *기본 설정*
* **개념**: 두 벡터 간의 각도(방향성)를 이용하여 유사도를 측정합니다.
* **특징**: Solar Embedding 벡터의 크기(Magnitude) 영향을 받지 않고 오직 정밀한 문맥적 방향성만을 비교합니다.
* **실험 결과**: 문서 길이 차이나 특정 단어의 빈도 폭에 영향을 받지 않고 질문과 가장 맥락이 일치하는 패시지를 안정적으로 검색해 내었습니다.

### 2) 내적 (Dot Product / Inner Product)
* **개념**: 두 벡터의 요소별 곱의 합을 측정합니다.
* **특징**: 벡터가 정규화(L2 Normalized)되어 있는 상태라면 코사인 유사도와 수학적으로 완벽히 동일한 순위를 반환합니다. 정규화되지 않은 벡터일 경우 크기가 큰 벡터가 더 높은 점수를 받는 경향이 있습니다.
* **실험 결과**: L2 정규화가 적용된 임베딩 환경에서는 코사인 유사도와 상위 k개 검색 결과가 동일하였으며, 계산 속도 측면에서 미세한 이점이 있었습니다.

### 3) L2 Norm (Euclidean Distance / 유클리드 거리)
* **개념**: 두 벡터 간의 직선 거리를 측정합니다 (값이 작을수록 유사함).
* **특징**: 공간상에서 두 지점의 물리적 거리를 계산하므로, 벡터의 길이가 다를 경우 고차원 공간에서 왜곡이 발생할 수 있습니다.
* **실험 결과**: 고차원(4096 차원) sparse/dense 공간 특성상 '차원의 커스(Curse of Dimensionality)' 영향을 받아, 키워드가 일부 중복되거나 짧은 패시지에 높은 점수가 부여되는 유의미한 순위 변동이 관찰되었습니다.

## 2. 키워드 검색 (BM25) vs 벡터 검색 (Dense Vector) 장단점 비교

| 구분 | 키워드 검색 (BM25 / Sparse) | 벡터 검색 (Vector / Dense) |
| :--- | :--- | :--- |
| **핵심 원리** | 텍스트 내 특정 단어의 빈도(TF) 및 역단어 빈도(IDF) 기반 매칭 | 문장/단어를 고차원 의미 공간에 임베딩하여 맥락 유사도 측정 |
| **장점** | - 고유명사, 품번, 기술 용어, 희귀 키워드 검색 정확도가 매우 높음<br>- 별도의 임베딩 연산 비용이 없음<br>- 검색 엔진의 작동 원리가 직관적이고 해석 가능함 | - 유의어, 동의어, 문맥적 의미 표현(의미론적 검색)에 강함<br>- 오탈자나 단어 표기가 달라도 맥락이 맞으면 찾아냄<br>- 다국어 간 의미 검색에 유용함 |
| **단점** | - 동의어나 다의어 처리가 어려움 (Semantic Gap)<br>- 질문과 문서 간 동일한 단어가 없으면 검색 불가 | - 고유명사, 숫자, 약어 등 정확한 텍스트 일치가 필요한 경우 성능 저하<br>- 임베딩 생성 및 인덱싱 모델 구동 비용 발생 |
| **최적 활용** | 제품 번호, 인명, 명확한 고유 키워드 검색 | 자연어 질문 기반 문맥 탐색 및 Q&A 시스템 |

### 💡 결론: Hybrid Search (RRF)의 필요성
키워드 검색은 **"정확한 단어 매칭"**에 강하고, 벡터 검색은 **"의미와 맥락 이해"**에 강합니다. RAG 파이프라인에서 두 방식의 단점을 보완하고 장점만을 결합한 **RRF(Reciprocal Rank Fusion) 하이브리드 검색**을 적용했을 때, 질문의 형태(고유명사 질문 vs 추상적 질문)에 상관없이 가장 높은 검색 정확도와 답변 품질을 확보할 수 있었습니다.
